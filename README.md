# Dylan Webs Memo

# ROL

Actuá como un **Senior Web Designer + Creative Developer + Brand Designer** especializado en sitios editoriales, portfolios digitales y presentaciones web para estudios creativos.

Tu trabajo es diseñar y desarrollar desde cero un **memo interactivo en formato presentación web** para mi negocio freelance:

**Dylan Webs — @dylan.webs.uy**

No quiero una landing page tradicional.

Quiero una mezcla entre:

- presentación profesional de negocio;
- memo estratégico;
- portfolio de estudio web;
- experiencia editorial interactiva.

El resultado debe sentirse diseñado específicamente para Dylan Webs, no generado a partir de una plantilla.

---

# 1. CONTEXTO DEL NEGOCIO

Dylan Webs es un servicio independiente de creación de páginas web para **negocios locales de Uruguay**, principalmente:

- restaurantes;
- barberías;
- gimnasios;
- tiendas;
- servicios profesionales;
- otros negocios que venden o consiguen clientes principalmente mediante Instagram, WhatsApp y Google.

No quiero posicionarme como:

- agencia de marketing;
- agencia de IA;
- consultora;
- empresa de automatizaciones;
- SaaS;
- agencia full-service.

El foco debe ser extremadamente claro:

> **Diseño y desarrollo páginas web para negocios locales.**

Mi propuesta no es simplemente “tener una web”.

Quiero ayudar a negocios que ya consiguen atención mediante Instagram, Google o recomendaciones a darle a sus clientes un lugar propio donde puedan:

- entender qué ofrece el negocio;
- ver precios;
- consultar servicios;
- conocer horarios;
- encontrar el local;
- reservar;
- comprar;
- pedir presupuesto;
- contactar por WhatsApp.

La web debe reducir fricción entre:

**“Encontré este negocio” → “Quiero hacer algo con este negocio”.**

---

# 2. IDEA CENTRAL

Toda la presentación debe girar alrededor de una tesis sencilla:

> **Instagram consigue la atención.  
> La web tiene que convertirla.**

No abuses de esta frase literalmente.

Usala como concepto rector.

El visitante debería terminar entendiendo:

> “Dylan no vende páginas porque sí. Entiende cómo una web puede resolver problemas concretos de un negocio local.”

- joven;
- seguro;

# 7. TIPOGRAFÍA

La tipografía es una parte MUY importante de la identidad.

NO uses automáticamente:

- Inter;
- Arial;
- Helvetica;
- Roboto;
- Poppins;
- Montserrat.

Tampoco quiero simplemente “una serif elegante + una sans genérica”.

Buscá una combinación tipográfica con personalidad.

Quiero:

### Display

Una tipografía moderna, expresiva y reconocible para:

- titulares enormes;
- números;
- statements;
- portadas.

Debe sentirse vinculada al mundo:

- diseño;
- tecnología;
- arquitectura;
- editorial contemporáneo.

### Secundaria

Puede existir una serif o tipografía de contraste utilizada únicamente en palabras o frases especiales.

### Mono

Puede utilizarse una monoespaciada para:

- índices;
- metadata;
- fechas;
- labels;
- navegación;
- pequeños datos técnicos.

La tipografía debe formar parte del diseño, no simplemente mostrar texto.

Usar cambios de:

- escala;
- peso;
- italic;
- tracking;
- posición;
- composición.

# 26. DETALLES QUE HACEN QUE NO PAREZCA IA

Muy importante.

NO usar continuamente:

- cards redondeadas;
- icono + título + párrafo;
- gradientes;
- glow;
- glassmorphism;
- blobs;
- emojis;
- tres columnas perfectamente iguales;
- botones enormes con gradiente;
- ilustraciones 3D genéricas.

Preferir:

- composición editorial;
- líneas finas;
- grids;
- tipografía como elemento gráfico;
- numeración;
- contraste de escala;
- whitespace;
- asimetría controlada;
- imágenes/mockups grandes;
- detalles inesperados pero coherentes.

Debe sentirse diseñado por una persona con criterio.

# 27. ACCESIBILIDAD

Mantener:

- HTML semántico;
- contraste correcto;
- focus states;
- navegación por teclado;
- aria labels cuando corresponda;
- prefers-reduced-motion;
- tamaños legibles;
- botones accesibles.

La estética nunca debe romper la usabilidad.

---

# 28. PERFORMANCE

Evitar dependencias innecesarias.

Optimizar:

- fuentes;
- imágenes;
- animaciones;
- JavaScript;
- layout shifts.

No instalar una librería de 200 KB para una animación que puede hacerse con CSS.

# 29. TECNOLOGÍA

Si se entrega como documento independiente:

HTML + CSS + JavaScript.

preferir Next.js + TypeScript.

# 30. CRITERIO FINAL

Antes de considerar terminado el trabajo, revisar cada pantalla y hacerse estas preguntas:

### Identidad

¿Esto podría pertenecer a cualquier agencia?

Si la respuesta es sí, rediseñarlo.

### Claridad

¿En menos de 30 segundos entiendo qué vende Dylan Webs?

Debe ser sí.

### Credibilidad

¿Hay alguna afirmación que Dylan todavía no pueda demostrar?

Eliminarla o identificarla como hipótesis.

### Visual

¿Todas las secciones usan el mismo layout?

Si sí, romper el ritmo.

### Copy

¿Hay alguna frase que suene como copy genérico de IA?

Reescribirla.

### Portfolio

¿FinTrack es el primer proyecto y tiene suficiente protagonismo?

Debe ser sí.

### Foco

¿Aparece algún servicio que distraiga de creación de páginas web?

Eliminarlo.
